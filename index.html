전사 확장 구조 검토

Claude Code를 활용하여 Meta 광고 자동 생성 솔루션을 직접 개발했습니다. 무신사, 메디힐 글로벌, 29CM 등 캠페인에서 검증된 프로세스를 타 캠페인으로 확장하기 위해 현황 및 고려사항을 정리합니다.

현재 적용: 무신사, 메디힐 글로벌, 29CM, 버킷스토어 월 처리량: 700건+ (26.07 무신사 기준) 개발 도구: Claude Code + Meta Marketing API
01

배경 및 문제 정의

디지털 광고 운영에서 반복적인 광고 세팅 업무는 많은 시간을 소비하면서도 휴먼 에러가 빈번하게 발생하는 영역이었습니다. 자동화를 통해 운영 효율성과 정확도를 동시에 개선할 수 있다고 판단하여 솔루션 개발에 착수했습니다.

⬛ 기존 프로세스
  1. 세팅 담당자가 대시보드에서 기존 광고 복사 후 광고명·문구·URL·매개변수 등 모든 요소 직접 입력
    ⚠ 입력 과정에서 휴먼 에러 빈발
  2. 이미지를 로컬 PC → 대시보드로 직접 업로드 후 등록
    ⚠ 소재 1개당 5분 이상 소요
  3. 별도 인원이 크로스체크 진행
✅ 변경 프로세스
  1. 이미지 포함, 세팅 요소를 자동생성 시트에 기재 후 솔루션 실행
  2. 솔루션이 Meta API로 광고 자동 대량 등록
  3. 세팅 담당자가 API 미지원 일부 요소만 업데이트 및 더블체크
02

솔루션 개요

Google Sheets를 입력 인터페이스로, 로컬 Flask 서버를 중개 레이어로, Meta Marketing API를 실행 엔드포인트로 연결하는 구조입니다. Claude Code를 활용해 기획·개발·운영 고도화를 직접 수행했습니다.

📊

Google Sheets

세팅 인터페이스. 광고명·문구·URL·소재 파일명 등 입력. VLOOKUP으로 campaign/adset ID 자동 매핑.

⚙️

Local Flask Server

로컬 실행 서버(포트 8765). 시트 데이터 파싱, 이미지 업로드, API 호출 조율. Apps Script 사이드바에서 트리거.

🔵

Meta Marketing API

v25.0. 광고 생성, 이미지 해시 발급, 지면별 소재 커스터마이징(asset_feed_spec) 지원.

🤖

Claude Code

솔루션 기획·개발·이슈 대응·고도화 전 과정에 활용. 별도 개발 인력 없이 실무 담당자가 직접 운영.

05

전사 확장 고려사항

무신사 캠페인에서 검증된 구조를 타 캠페인으로 확장하기 위해 아래 사항을 고려해야 합니다.

1

광고주별 액세스 토큰 발급 및 BM 권한 설정 필요

Meta Marketing API 사용에는 두 가지 자격이 필요합니다. Meta App(App ID·App Secret)은 매드업이 한 번 등록하여 팀 단위로 공유하는 API 사용 자격이며, 액세스 토큰은 특정 광고 계정에 실제 접근하는 열쇠로 BM 시스템 유저 단위로 발급됩니다. 현재는 광고주 BM에서 시스템 유저를 생성해 광고주별 토큰을 각각 발급받는 방식으로 운영 중입니다. 전사 확장 시에는 매드업 BM에 시스템 유저를 생성하고 광고주가 계정 접근 권한을 매드업 BM에 부여하면, 토큰을 통합 관리하거나 팀 단위로 구분하는 방식으로 온보딩 절차를 간소화할 수 있습니다.

2

서버 포트 분리 방식으로 독립 운영

현재는 캠페인별로 폴더를 복사하고 포트를 분리하여 독립 서버로 운영하는 방식으로 진행하고 있습니다. 캠페인 수가 늘어날 경우 단일 서버에서 시트 ID로 분기하는 구조로의 전환도 고려할 수 있습니다.

3

캠페인별 세팅 컨디션 차이 대응

광고주·캠페인마다 활용하는 세팅 항목이 다릅니다. 실제 캠페인 간 주요 차이점은 다음과 같습니다.

  • tracking_specs: 무신사는 픽셀 + 앱 트래킹 스펙을 모두 사용하지만, 메디힐 글로벌은 MMP 별도 운영으로 tracking_specs 미사용 — 코드 분기 처리 필요
  • appsecret_proof: 메디힐은 Meta 보안 정책 상 appsecret_proof 파라미터 추가 서명이 필요해 별도 구현 적용 (무신사는 미사용)
  • 소재 타입: 무신사는 이미지 전용(upload_image)이지만, 메디힐은 영상 소재 지원(upload_media) — 확장 시 소재 업로드 로직 분기 필요
  • CPAS 카탈로그 광고: Meta API 정책상 카탈로그 광고(promoted_object 방식)는 자동 생성 불가 — 수동 세팅 영역으로 별도 관리

캠페인 온보딩 시 세팅 컨디션을 사전 정의하고 config.py에 반영하는 작업이 필요합니다.

4

Meta API 미지원 항목은 수동 처리 유지

URL 매개변수(url_tags) 등 일부 항목은 Meta API 정책상 광고 생성 시점에 적용이 제한됩니다. 이 항목들은 자동화 이후 담당자 수동 업데이트가 필요하며, 캠페인 온보딩 시 자동화 가능 항목과 수동 처리 항목을 명확히 구분해야 합니다.

5

배포 시 고유값 제거 버전으로 제공 권장

현재 코드는 무신사 캠페인 기준으로 작성되어 GCP 서비스 계정 JSON, Meta 액세스 토큰, 광고 계정 ID 등 고유 인증정보가 포함되어 있습니다. 타 캠페인 적용 시에는 해당 값을 빈값 또는 플레이스홀더로 처리한 버전으로 배포하여, 담당 AE가 온보딩 시 직접 값을 입력할 수 있도록 안내하는 방식을 권장합니다.

06

추가 확장 가능성

본 솔루션의 구조(시트 입력 → 로컬 서버 → 매체 API 호출)는 Meta에 종속되지 않습니다. 메디힐 글로벌 캠페인에서 동일한 코드 아키텍처를 기반으로 TikTok Ads API 및 싱글원 API를 활용한 광고 자동 세팅 솔루션을 추가 개발한 사례가 있으며, API를 공식 지원하는 매체라면 동일한 방식으로 적용 가능합니다. 이를 통해 전사 광고 운영 자동화 범위를 매체 단위로 점진적으로 넓혀갈 수 있습니다.
